## 1. 本轮目标：先交付一版完整、可验证的正常工作版本

本轮只追求一个结果：形成一套可以从主电源供电、给超级电容充电、主电源异常时自动切换到超级电容、并在负载端维持规定输出的完整系统。

V0.1 的工作顺序：

1. 先确认官方赛题硬指标及负载边界。
2. 证明当前 4S×20F 架构在真实候选器件边界下具备能量可行性。
3. 关闭充电、Boost、单体保护、主备切换四个必要模块的关键问题。
4. 把模块接入同一版原理图、接口和整机模型。
5. 通过整机仿真和设计审查后，形成 V0.1 仿真候选。
6. BOM、封装、ERC/DRC 和安全验证具备放行条件后，才进入首板生产和实物测试。

**V0.1 不是“文件齐全版”，而是“端到端功能闭环版”。** 单独的模块测试通过，不等于整机通过。

## 2. 指标分级：纠正此前计划中的混淆

赛题原件标有保密提示。公开仓库不上传赛题 PDF、截图、完整评分表或未经授权的原文摘录。团队成员必须使用队内获准持有的赛题原件核对具体数值；本文件只定义执行规则和指标类别。

| 分类 | 内容 | V0.1 处理方式 |
|---|---|---|
| 官方硬指标 | 输入、输出、满载持续时间、切换期间输出下限、效率、纹波、输入过压、超级电容过充、输出短路及自动切换 | 必须逐项按赛题原件验收；不允许用内部模型目标替代官方门槛 |
| 内部设计裕量 | 当前项目使用的 12W / 1.2s 能量预算目标 | 保留为优选裕量，不得误写成官方最低要求；若未达到，先判断是否已满足官方门槛，再记录剩余风险 |
| 内部安全目标 | 单体欠压到实际放电电流隔离不超过 5ms、监测失效默认禁止充放电、故障后重新武装 | 不是赛题评分条目，但属于本项目安全设计约束；不得为了赶进度直接删除。无证据时不得宣称安全闭环 |
| 模型假设 | 85% Boost 效率、EOL 容量、DC ESR、路径电阻、初始电压等 | 只能作为模型输入；必须注明来源、保证等级和待测属性，不得冒充实测或厂家保证 |
| 方案选择 | 4S×20F、Eaton 候选、TPS61088、TPS54302、TPS2121/eFuse | 是当前实现路线，不是赛题强制架构；V0.1 冻结期间不随意换架构 |
| 后续优化 | 更高效率、更低纹波、简易 BMS、故障记录、小型化、成本优化 | 放到 V0.2；不得阻塞 V0.1，除非它关系到硬指标、安全或器件不可采购 |

### 必须分开报告的效率

- Boost 功率级效率。
- 超级电容放电到负载端的放电效率。
- 赛题定义的端到端效率。

三者测量边界不同。不能用 Boost 的模型效率代替放电效率，更不能代替端到端效率。具体计算边界、能量积分区间和仪器测点由整机负责人写入测试方案，并与赛题原件定义一致。

### 必须分开报告的时间

- 官方规定的满载备电持续时间。
- 内部 1.2s 裕量目标。
- 从单体欠压阈值越界到实际电流隔离的保护响应时间。

三个时间的起止事件不同，禁止混用。

## 3. V0.1 范围与冻结边界

### 本轮必须完成

- 12V 主输入路径及输入异常保护。
- 超级电容充电路径，包含 CC/CV 工作过程和硬件过充禁止。
- 当前 4S×20F 储能候选的能量、ESR、失配和温度边界核算。
- TPS61088 Boost 功率级及其限流、电感、电容和动态验证。
- 四串单体监测、欠压保护、默认禁止和故障重新武装。
- TPS2121 主备选择、eFuse 资格判断、BACKUP_READY 和残压故障拒绝。
- 统一控制接口、故障状态和整机联锁。
- 整机输出、保持时间、效率、纹波、切换和保护测试方案。
- 关键器件完整 MPN、封装、额定值、保证参数和采购可行性审查。
- KiCad 原理图、网表、ERC、PCB/EDA 导入检查及生产放行清单。

### 本轮暂缓

- 为追求加分而进行的极限效率优化。
- 低于比赛基础纹波要求的过度优化。
- 完整智能电量算法、复杂 UI 和非必要通信功能。
- 未证明必要性的架构重构。
- 仅为了降低成本而替换已经进入验证的关键保护器件。
- Rust/其他平台、额外拓扑和与 V0.1 无关的研究分支。

### 架构冻结规则

当前 4S×20F 是 V0.1 的研发候选基线。除非出现以下任一情况，否则不启动架构替换：

1. 经可复跑模型证明无法满足官方硬指标；
2. 关键器件无法采购，且没有合格替代料；
3. 保护机制无法形成可验证的安全状态；
4. 现有方案的成本或尺寸使参赛目标明显不可行。

如触发变更，必须提交“现方案失败证据—替代方案—性能/成本/风险比较—重新验证清单”，由总集成负责人批准后执行。2S/其他拓扑研究只作为隔离研究，不得混入 V0.1。

## 4. 工作分组与文件边界

每个工作组只修改自己负责的目录和接口。共享接口、总验收矩阵、总看板由总集成负责人维护。

| 工作组 | 唯一职责 | 主要交付 | 不得擅自修改 |
|---|---|---|---|
| A. 整机与能量预算 | 负载边界、储能预算、最坏工况、系统接口和整机联合验证 | 参数来源表、可复跑能量模型、负载端波形、通过/失败角点 | Boost/充电/保护模块内部设计 |
| B. Boost 功率级 | TPS61088、RILIM、开关频率、电感、电容、效率、启动/短路/阶跃 | 器件级仿真、RAW/LOG、限流矩阵、保证 Isat 证据 | 充电器、BMS、主备控制逻辑 |
| C. 充电系统 | TPS54302、CC/CV、组端/单体 OVP、充电许可和故障锁存 | 充电原理图、环路与动态模型、停充波形 | Boost 功率级、放电切换 |
| D. 单体保护 | BQ76905、采样配置、CELL_PERMIT、欠压隔离和重新武装 | 配置证据、最坏时间预算、故障测试、隔离波形 | 充电环路、TPS2121 选型 |
| E. 主备切换 | TPS2121、eFuse、BACKUP_READY、预启动、残压拒绝、主源恢复 | 引脚/网表审查、状态机、残压故障仿真、切换波形 | 超级电容充电器、Boost 内部补偿 |
| F. 采购与 EDA | 关键器件采购、替代料、封装、BOM、嘉立创导入和生产文件审查 | 可采购 BOM、供应商证据、替代料影响表、ERC/DRC/导入记录 | 未经模块负责人批准替换电路参数 |
| G. 总集成与发布 | 统一基线、接口控制、跨模块冲突、验收矩阵、版本发布 | 集成提交、整机回归、发布报告和看板 | 不得把未验证结果标成通过 |

### 防止重复开发

- 每个工作组认领一个明确模块；同一文件同一时间只有一个负责人。
- 发现其他组的缺陷时，提交问题和复现证据给负责人，不直接跨目录修补。
- 总集成负责人维护接口定义和总验收矩阵；专项组可以提出修改，不直接改总表。
- 旧分支的成果先复核，再选择性 cherry-pick；不允许把分叉分支整体合并。
- 不重新生成已有数据，除非分析程序、模型参数或验收标准发生变化；需要重跑时保留旧数据并记录新旧差异。

## 5. 七阶段执行顺序

| 阶段 | 目标 | 退出条件 |
|---|---|---|
| S0：计划与基线冻结 | 对齐赛题、负载、接口、仓库基线和负责人 | 官方指标已逐项映射；所有任务有唯一负责人；分支边界明确 |
| S1：可行性先行 | 先回答储能是否够、Boost 是否够、关键料是否买得到 | 使用候选器件保证/最坏参数完成能量角点；关键电感与保护器件有可行采购路径 |
| S2：模块闭环 | 分别完成 Boost、充电、单体保护、主备切换 | 每个模块有独立复跑命令、参数、日志、波形和失败记录 |
| S3：接口闭环 | 核对电源域、控制许可、故障撤销和启动时序 | 网表接口一致；无 PG 残压误判；默认状态和重新武装明确 |
| S4：整机仿真 | 运行正常、边界、故障和恢复工况 | 官方硬指标有对应整机证据；所有未通过项明确阻塞发布 |
| S5：设计与制造审查 | 冻结 MPN、封装、BOM、原理图和 PCB | 关键料可采购；ERC/DRC 通过；热路径、测试点和生产文件审查完成 |
| S6：V0.1 首板与实测 | 制作样机并完成真实负载、切换和保护测试 | 满载供电、切换电压、效率、纹波、温升和保护时序有实测记录 |

**11月30日目标仅为 S4 的 V0.1 整机仿真评审候选。** 若 S1–S4 的证据不满足退出条件，必须如实延期；不得为了日期将 MODEL_ONLY 或 NOT_TESTED 改成 PASS。PCB 下单日期由 S5 决定，不预先承诺。

## 6. 本轮优先级

### P0：决定 V0.1 能不能成立

1. 赛题硬指标与负载规格逐项映射，确认输出允许窗口、切换中断定义和效率测量边界。
2. 用当前候选物料重新核算保持时间，重点处理已出现的低于目标工况。
3. 确认 Boost 电感保证最小饱和电流、TPS61088 限流和最坏输入角点。
4. 证明 CC/CV 充电、组端/单体过压和异常默认停充。
5. 证明 CELL_PERMIT 从欠压到实际电流隔离的完整链路。
6. 证明 BACKUP_READY 不会把 eFuse 断开后的残压误判成可用备源。
7. 确认关键器件真实可采购，避免完成仿真后才发现无料可买。

### P1：整机与制造准备

- 统一原理图和跨页网表。
- 整机联合仿真与故障注入。
- 嘉立创导入前后网名、引脚和封装核对。
- BOM、ERC/DRC、热设计、测试点和生产文件审查。

### P2：V0.2 竞赛优化

- 更高效率、更低纹波。
- 简易 BMS、电量估算和故障记录。
- 小型化、成本优化和器件降额优化。
- 所有优化均以 V0.1 已通过的基线为对照，保留回归测试。

## 7. 证据与状态定义

所有报告必须按以下级别标记，禁止越级：

1. **设计完成**：原理图/参数/方案存在。
2. **单元测试通过**：脚本或局部逻辑测试通过。
3. **行为仿真通过**：状态机或平均模型通过。
4. **SPICE 仿真通过**：指定网表和模型在指定工况下通过。
5. **整机联合仿真通过**：同一集成提交上的跨模块仿真通过。
6. **EDA 检查通过**：指定版本 ERC/DRC、网表和封装核对通过。
7. **实物测试通过**：真实板卡、真实负载、仪器测量和原始数据齐全。

每项证据至少记录：仓库、分支、完整 commit SHA、文件路径、运行命令、工具版本、输入参数、通过标准、实际结果、RAW/LOG/CSV/波形和 SHA256。失败结果必须保留。

## 9. V0.1 发布包

- 系统框图、接口表和状态/故障流程。
