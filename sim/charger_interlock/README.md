# 充电许可锁存行为参考

目标为上电默认关断，故障撤销许可，故障消失后必须重新发出 ARM 请求。ARM 是启动请求。持续运行期间的关断由保护条件或单独的撤销许可输入完成。四组布尔输入分别代表电源正常、基准有效、组端及抽头采样有效、保护链无故障。任何一组撤销均清除运行许可。故障会清除此前对 ARM 低电平的记录。系统就绪后先观测到 ARM 为低，才接受下一次高电平。若 ARM 上升与系统就绪同时被采到，本次请求不被接受。

运行 `python3 -B sim/charger_interlock/check_policy.py`。共检查 128 个布尔组合和 4 组时序，包括上电保持高、就绪与 ARM 同时上升、故障后保持高、故障期间的完整 ARM 脉冲。此脚本描述目标行为。现有电路的参考就绪、输入欠压时输出状态、硬件锁存及传播时间需分别验证。

## 与现有充电页的接口对照

`python3 -B sim/charger_interlock/check_integration.py` 复现三个架构在同一组八步输入下的结果。[对照数据](integration.csv)

- 现有台架许可持续有效时，若保护释放，串联门控可以重新导通。
- 把锁存输出接到 Buck 许可、同时把 Buck EN 当成锁存的就绪输入，会形成启动循环依赖。默认关断时无法使 EN 成为有效的启动前提。
- 合入候选需要独立的原始故障状态。锁存前的就绪条件取辅助电源、基准有效、采样完整及独立过压状态。现有已缓冲的 Buck EN 可继续位于串联开关的末级门控。

对照只覆盖稳态数字信号。独立故障输出、参考就绪、异步清零延时及欠电复位还需要硬件实现和验证。
